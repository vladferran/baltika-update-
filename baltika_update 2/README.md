# Бот учёта смен «до выходных»

Telegram-бот для сменного графика: считает время до конца смены и до выходных,
напоминает о выходе на работу и подбадривает перед концом смены.
Публичный — каждый сотрудник задаёт свой цикл при `/start`.

## Логика цикла

График описывается строкой символов, которая крутится бесконечно от якорной даты:

| символ | значение |
|--------|----------|
| `Д` | дневная смена |
| `Н` | ночная смена (переходит через полночь) |
| `В` | нерабочий день |

Пример «Балтики»: `ДДВННВВВ` — 2 дневные, выходной, 2 ночные, 3 выходных.

Два принципиальных момента, которые бот считает правильно:

1. **Одиночный `В` внутри блока — это не выходные, а передышка.** Настоящими
   выходными считается блок от `weekend_min_days` дней подряд (по умолчанию 2).
2. **Ночная смена съедает утро первого выходного.** После ночи 20:00–08:00
   свобода наступает в 08:00 следующего дня, а не в полночь.

## Уведомления

| Событие | По умолчанию | Настраивается |
|---------|--------------|---------------|
| За 2 суток до смены | вкл | вкл/выкл |
| За сутки до смены | вкл | вкл/выкл |
| Перед сменой | за 2 часа | 1 / 2 / 3 ч / выкл |
| «Скоро домой» | за 80 мин до конца смены (18:40 при смене до 20:00) | 30 / 60 / 80 / 120 мин / выкл |
| «Выходные начались» | вкл | вкл/выкл |
| Развозка от метро на смену | за 30 мин | 15 / 30 / 45 / 60 мин / выкл |
| Развозка с завода после смены | за 30 мин | то же |
| Погода в сообщениях | вкл | вкл/выкл |
| Опрос «по пиву» после дневной | за 35 мин | вкл/выкл |
| Просьба отметиться | через 30 мин после начала смены | вкл/выкл |
| Автоочистка чата | через 3 часа | 1 / 3 / 6 / 12 ч / выкл |

Во время смены длинные напоминания («за сутки», «за 2 дня») не приходят —
человек и так на работе.

Тексты берутся из таблицы `phrases`, а не из кода: новую шутку можно
добавить обычным `INSERT` без деплоя.

```sql
INSERT INTO phrases (category, level, text, enabled)
VALUES ('almost_home', 2, 'Осталось {left}. Держись.', true);
```

Категории: `d2`, `d1`, `soon`, `almost_home`, `counting`, `resting`,
`between`, `freedom`, `bus_to`, `bus_from`. Уровни: 1 — лёгкий подкол, 2 — норм ирония, 3 — жёстко.
Плейсхолдеры: `{left}`, `{weekend}`, `{kind}`, `{when}`, а для развозки
дополнительно `{station}`.

## Развозка

Четыре маршрута корпоративных автобусов: Парнас, Проспект Просвещения,
Гражданский проспект, Девяткино. Расписание статичное, лежит в `app/shuttle.py`,
будни и выходные различаются автоматически по дню недели.

Бот подбирает рейсы под конкретную смену:

- **на работу** — последние рейсы от метро, отправляющиеся не позже чем за
  `bus_buffer_min` минут до начала смены (по умолчанию 20);
- **с работы** — первые рейсы с завода после окончания смены, при
  необходимости переходя на следующий день.

Пуш о развозке приходит за `notify_bus_min` минут до отправления
(по умолчанию 30, настраивается 15/30/45/60 или выключается).
Ближайшие рейсы также подклеиваются к ответу `/skolko`.

## Погода

Источник — [Open-Meteo](https://open-meteo.com): без ключа, без регистрации,
свободно для некоммерческого использования. Координаты завода зашиты
в `app/weather.py` (`PLANT_LAT` / `PLANT_LON`).

Ответ кэшируется на 15 минут, так что сколько бы человек ни жало `/pogoda`,
к API уходит максимум один запрос в четверть часа. Если сервис недоступен —
погодная строка просто не добавляется, а уведомление о смене уходит как обычно.

Погода подклеивается к `/skolko`, к пушу за N часов до смены и к «скоро домой»
(там — прогноз на конец смены, чтобы понимать, во что одеваться домой).
Отключается тумблером в `/nastroiki`.

## Опрос «по пиву»

За `BEER_LEAD_MIN` минут до конца **дневной** смены (по умолчанию 35) всем,
у кого включён тумблер, приходит вопрос с двумя кнопками. После ночных
опрос не идёт.

Событие одно на момент окончания смены — все, кто заканчивает в одно время,
попадают в общий список. В этом и смысл: ответивший «да» сразу видит, кто
ещё согласился, а в момент конца смены участникам уходит итоговый состав
и место сбора.

Голос перезаписывается: передумать можно до самого конца смены.
Ответившему «нет» бот отвечает нейтрально и больше в этот день не пишет —
никаких повторных предложений и подколов за отказ.

Место встречи задаётся переменной `BEER_PLACE`, для конкретного события
меняется командой `/pivo_mesto` (только для id из `ADMIN_IDS`).

## Стаж и посещаемость

Дата устройства задаётся командой `/ustroilsya 15.03.2024`, после чего
`/stazh` показывает карточку: календарный стаж, отработанные смены, часы,
минуты, пересчёт в «суток непрерывной работы», расклад по дневным и ночным,
пропуски по причинам и полоса выполнения.

**Принцип учёта.** План берётся из графика, руками отмечаются только
исключения. Прошедшая смена без отметки считается отработанной — иначе один
забытый день ломал бы всю статистику. Сколько таких смен, карточка честно
показывает отдельной строкой.

Отметиться можно тремя способами:

- кнопками в пуше, который приходит через 30 минут после начала смены
  (отключается тумблером);
- командой `/otmetka` в любой момент смены;
- задним числом за период: `/bolnichny 10.09.2026 14.09.2026`.

Статусы: ✅ вышел, 🤒 больничный, 📄 отгул, 🚫 не вышел. Отметка
перезаписывается, ошибиться не страшно.

Календарный стаж считается через якорь «дата устройства + N лет M месяцев»:
наивная арифметика даёт отрицательный остаток на датах вроде 31 января
против 1 марта.

## Автоочистка чата

Каждое сообщение бота попадает в очередь `pending_deletes` с моментом смерти.
Срок не фиксированный, а смысловой — сообщение живёт ровно пока полезно:

| сообщение | исчезает |
|-----------|----------|
| «за 2 дня» / «за сутки» / «за 2 часа» | в момент начала смены |
| «скоро домой» | через 30 мин после конца смены |
| развозка | через 20 мин после отправления автобуса |
| опрос «по пиву» | через 2 часа после конца смены |
| итоговый список участников | через 8 часов |
| ответы на команды | через `clean_after_min` (по умолчанию 3 часа) |

Ответ на команду удаляется вместе с самой командой, так что переписка
не копится. `/clean` вычищает всё немедленно, тумблер в `/nastroiki`
переключает 1 / 3 / 6 / 12 часов или выключает совсем.

Telegram разрешает боту удалять сообщения не старше 48 часов — просроченные
записи молча выбрасываются из очереди.

## Панель управления

`/admin` — только для id из `ADMIN_IDS`. Для остальных команда не отвечает
вообще, чтобы не выдавать её существование.

- **📊 Статистика** — пользователи, активные, с развозкой, согласия за неделю, разбивка по графикам
- **👥 Пользователи** — последние 20 с их сегодняшней сменой
- **🍺 События** — последние 7 сборов с раскладом да/нет
- **🧹 Очередь удаления** — размер очереди и принудительная зачистка
- **📢 Рассылка** — текст с предпросмотром и подтверждением, отправка под семафором

- `/pivo` — кто идёт после смены и куда

## Развёртывание

Автоматически на чистый сервер:

```bash
tar -xzf baltika_bot.tar.gz && cd baltika_bot
sudo bash deploy/install.sh
nano /opt/baltika_bot/.env      # BOT_TOKEN и пароль БД
sudo systemctl start baltika-bot
```

Вручную:

```bash
sudo -u postgres createuser baltika -P
sudo -u postgres createdb -O baltika baltika_bot

cd /opt && git clone <repo> baltika_bot && cd baltika_bot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env

sudo cp deploy/baltika-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now baltika-bot
journalctl -u baltika-bot -f
```

Таблицы создаются автоматически при первом запуске, банк фраз засеивается
идемпотентно (повторный запуск не плодит дубликаты).

## Обновление схемы

Новые колонки добавляются миграцией — `create_all` существующие таблицы
не трогает:

```bash
sudo -u postgres psql -d baltika_bot -f deploy/migrate_002_shuttle.sql
sudo -u postgres psql -d baltika_bot -f deploy/migrate_003_weather.sql
sudo -u postgres psql -d baltika_bot -f deploy/migrate_004_beer.sql
sudo -u postgres psql -d baltika_bot -f deploy/migrate_005_cleanup.sql
sudo -u postgres psql -d baltika_bot -f deploy/migrate_006_stats.sql
```

Воркер тикает раз в 60 секунд, дедупликация через `sent_log`
(`UNIQUE user_id + key`) — рестарт сервиса не приводит к повторным пушам.
Окно срабатывания 15 минут: если бот полежал, уведомление уйдёт с опозданием,
а не потеряется. Рассылка идёт под семафором на 20 параллельных отправок,
`TelegramRetryAfter` обрабатывается, заблокировавшие бота деактивируются.

## Telegram Mini App

Веб-интерфейс живёт в `webapp/index.html` и отдаётся тем же процессом бота
(aiohttp, `127.0.0.1:WEB_PORT`). Наружу его выставляет обратный прокси с HTTPS.

Переменные в `.env`:

```
WEB_PORT=8080
WEB_URL=https://<твой-поддомен>/
```

Пример для Caddy (`/etc/caddy/Caddyfile`):

```
<твой-поддомен> {
    reverse_proxy 127.0.0.1:8080
}
```

Затем `sudo systemctl reload caddy` и `sudo systemctl restart baltika-bot`.
Если `WEB_URL` пустой, кнопка «Приложение» не появится, сервер всё равно
поднимется на локальном порту.

Безопасность: каждый запрос несёт заголовок `X-Init-Data` — строку initData
от Telegram. Бэкенд проверяет её HMAC по токену бота и отклоняет подпись,
которая старше 24 часов. Без валидного initData API ничего не отдаёт.

API:

- `GET /api/state` — все данные для экрана (смена, график, развозка, стаж, пиво, погода, настройки)
- `POST /api/mark` — `{"status": "worked|sick|vacation|dayoff|absent"}`
- `POST /api/beer/vote` — `{"event_id": 1, "yes": true}`

Тесты подписи: `tests/test_webapp.py`.
